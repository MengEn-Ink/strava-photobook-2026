# 高光摄影海报封面与年度总结跨页设计

## 目标

把当前仅包含年份和副标题的封面升级为由真实骑行照片、年度数据和路线印记共同构成的海报；同时把年度数字列表升级为有叙事节奏的双页总结。两者必须使用真实 Strava 数据，适配全部 19 套主题，并保持静态 GitHub Pages、桌面双页和手机单页都可用。

## 调研结论

- Strava Year in Sport 最值得借鉴的是“一屏一个强结论”、超大数字和短年度文案，而不是具体皮肤。
- Garmin Connect 的优势是指标、单位、纪录范围清楚，适合作为数据可信度基线。
- Relive 擅长把路线作为故事线索，适合作为背景层而不是统计主体。
- Rapha 和骑行赛事海报擅长用纪实照片、裁切和期刊信息建立文化感。

本项目不复制任何竞品页面；组合以上方法，并以活动照片、全年轨迹、主题色和月份时间轴形成自己的识别系统。

## 封面定稿

采用“B2 撞色运动海报骨架 + B1 纪实照片选择逻辑”。

### 信息层级

1. 高光照片占封面上部约 68% 至 74%，是唯一主视觉。
2. 超大年份与照片发生叠压，但必须避开人物面部和重要标识。
3. 下部主题主色信息区只展示短标题、骑行次数、年度里程和活跃月份。
4. 主题强调色用于年份、微型标签和路线印记，不再增加第三种强调色。
5. 封面不显示高光活动的长标题、说明或多个徽章。

### 自动选图

先从已入册照片中选择，而不额外消耗 Strava API。候选照片必须可读取、尺寸足够且来自当年活动。排序分数由以下信号组成：

- 横图优先，因为更容易形成上图下信息的海报结构；
- 活动的编辑高光分、Kudos、PR、距离与爬升；
- 照片所属活动有明确标题；
- 构图安全性：预留文字所在区域，优先选择主体不占满全画面的照片。

首版不引入人脸识别或云端视觉模型。生成器为候选照片输出可预测的 `object-position`，并支持后续人工覆写。

### 降级策略

如果没有合格照片，封面自动降级为年度路线海报：主题主色底、强调色路线、超大年份与三项核心数字。不得生成空图片框、远程占位图或空白封面。

## 年度总结跨页定稿

删除当前独立标题页与年度数字列表，合并为一个完整跨页。

### 左页：年度宣言

- 年度总里程为唯一超大数字。
- 一句固定结构的年度文案：“这一年，你用两个车轮重新画了一遍城市与山野。”
- 底部三项：骑行次数、移动时间、累计爬升。

### 右页：年度节奏与纪录

- 月份柱图按实际总里程绘制，最高月份使用主题强调色。
- 四项纪录：最活跃月份、最长单骑、收到 Kudos、赛段 PR。
- 最长单骑显示活动名，但限制为一行。
- 年度路线只作低对比度背景纹理，不影响标题或柱图。

年度总结之后继续展示全年轨迹热力图。这样阅读顺序为：情绪封面 → 年度结论 → 时间节奏 → 空间轨迹 → 按月活动故事。

## 主题与响应式

- 所有颜色只引用 `--theme-primary`、`--theme-accent`、`--theme-accent-ink` 和主题纸色。
- 深浅主题都必须满足文字对比度；照片上的文字使用独立暗色遮罩，不依赖照片本身。
- 桌面以双页关系设计；手机按单页依次展示封面、年度宣言、年度节奏、热力图。
- 所有文字限制行数和安全区，不能与翻页阴影、页脊或底部状态重叠。

## 数据与模块边界

- 新增封面选择模块，只负责根据活动与本地照片返回 `CoverSelection`，不负责 HTML。
- 新增年度汇总数据结构，集中计算月份总里程、活跃月份和纪录，页面渲染不重复计算。
- `book.py` 只编排封面、年度跨页、热力图和活动页。
- 现有照片数量、月份排序、高光筛选和发布安全门禁保持不变。

## 验证标准

- 单元测试覆盖封面选择稳定性、无图降级、月份聚合、纪录计算和长标题截断。
- 页面契约验证封面包含本地照片或路线降级标记，且年度总结恰好两页。
- 布局门禁覆盖标题、年份、指标、柱图与安全区。
- 浏览器检查至少覆盖 1440×900 与 390×844，并切换一个深色主题和一个浅色主题。
- 发布校验继续要求 40 张照片、年度热力图、月份时间轴、零空白页和零内部页码。

## 后续优化优先级

1. 本次：海报封面、年度总结跨页、自动选图与降级。
2. 下一阶段：给月份时间轴增加里程密度提示，并让月度跳转与年度柱图互相对应。
3. 下一阶段：生成“年度十大活动”索引页，按照片、Kudos、PR 与故事完整度综合排序。
4. 可选：提供封面照片人工选择与裁切位置配置，不改变默认自动流程。
5. 暂不做：在线地图瓦片、社交分享后台、动态视频封面和依赖云端模型的选图。
